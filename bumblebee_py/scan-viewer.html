❓ Why am I seeing zero potential exposures?

Zero findings does not prove zero vulnerabilities. Possible reasons:

  1. Scan was run without --exposure-catalog.
  2. Catalog was loaded but no package/version matched.
  3. Catalog freshness cannot be verified (no metadata).
  4. Threat-intel catalog covers malicious packages, not general CVEs.
  5. Matcher uses exact version matching only.
  6. Some scanned ecosystems may not be covered by the catalog.

Zero findings means Bumblebee did not emit finding records for this snapshot. It does not mean the system has no risk.

⚖️ Severity vs priority

Severity comes from the threat-intel catalog.

Priority is generated by the dashboard from severity plus local context (direct dependency, install scope, confidence, lifecycle scripts).

A high-severity catalog match in a direct dependency is higher priority than the same match in a low-confidence stale source file.

Priority source: Dashboard heuristic

📖 How recommendations are generated

  • Review immediately — finding severity critical/high + package is a direct dependency or global/user scope. Source: Dashboard heuristic using scanner + catalog data.
  • Check lifecycle scripts — package has a finding and has_lifecycle_scripts is true. Source: Dashboard heuristic using scanner traits.
  • Validate source file — finding or package confidence is low/medium. Source: Dashboard heuristic using scanner confidence.
  • Refresh threat intel — no catalog metadata present. Source: Dashboard heuristic using snapshot metadata.
  • No immediate action — package has inventory traits only, no catalog-backed finding. Source: Dashboard heuristic.
